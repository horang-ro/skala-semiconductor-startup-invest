## 0. 문서 사용 원칙

### 0.1 출처 등급

모든 수치와 사실 뒤에 `[기업코드-번호]` 형식으로 출처를 붙였습니다. 출처 목록은 문서 맨 끝 **9장 참고 자료**에 있습니다. 각 출처에는 아래 등급 중 하나를 달았습니다.

| 등급 | 뜻 | 예시 |
|---|---|---|
| `공시` | 법정 공시 원문 | DART 감사보고서, SEC Form D |
| `공식` | 회사 또는 파트너사가 직접 낸 자료 | 홈페이지, 보도자료, 제품 데이터시트 |
| `학술·특허` | 논문, 학회 발표, 특허 문서 | arXiv, Nature, ISCA, Google Patents |
| `제3자` | 이해관계가 없는 기관의 측정이나 평가 | MLPerf(MLCommons), BDTI 독립 평가 |
| `언론` | 기자가 취재해 보도한 기사 | 한국경제, Reuters, 더벨 |
| `2차 DB` | 민간 기업정보 DB | NICE(사람인 경유), THE VC, CB Insights, Forge |
| `2차` | 원 출처를 밝히지 않은 가공 자료나 블로그 | 분석 블로그, 순위 사이트 |
| `출처 불명` | 원자료에 인용 번호는 있지만, 그 번호가 없는 문서이거나 다른 회사 기사인 경우 | 3.4절 참고 |

### 0.2 데이터 해석 규칙 (5개 원자료의 공통 규칙을 합침)

1. **"미공개"는 0원이 아니다.** 공개 자료에서 확인할 수 없다는 뜻이다. 빈칸을 0으로 채우거나, 설립 전·판매 전 기간을 0으로 채우지 않는다.
2. **투자금, 수주 약정, 기업가치, 추정 매출은 매출이 아니다.** 감사받은 연간 매출과 다른 칸에 기록한다.
   * 예: Groq의 사우디 $1.5B 약정
   * 예: Etched의 $1B 수주 잔고
3. **매출 데이터는 성격을 구분한다.** 성격은 아래 7가지이며, 같은 성격끼리만 시계열로 묶는다.
   * 공시(감사)
   * 공시(감사받지 않은 비교 수치)
   * 정부 DB 인용 보도
   * 2차 DB
   * 언론 보도
   * 회사 전망
   * 미공개
4. **회사 목표치는 실적이 아니다.** 예: "2026년 매출 600억 목표"
5. **TOPS는 조건이 같을 때만 비교한다.** 아래 조건이 다르면 숫자를 바로 줄 세우지 않는다.
   * 정밀도: INT8 / INT4 / FP8 / FP16 / BF16
   * 최대 스펙인지, 실측인지
   * 단위: 칩 / 카드 / 멀티칩
   * 워크로드
   * 클럭
   * 전력 범위
6. **TOPS/W는 회사 주장과 독립 측정을 구분한다.** 이 문서의 TOPS/W 계산값은 회사가 발표한 최대 성능을 발표 전력의 **보수적인 값(더 큰 전력)**으로 나눈 값이다.
7. **R&D 과제 지원금, 신주 투자, 구주 거래, 누적 조달액은 합산하지 않는다.**
8. **파트너 로고, 공동 연구, 생태계 가입은 고객 매출의 증거가 아니다.** 투자자 목록도 구매 계약이 아니다.
9. **제품 성숙도는 아래 단계로 나눠서 판단한다.**

   `시뮬레이션 → FPGA/시제품 → 테이프아웃 → 첫 실리콘 → 샘플/파일럿 → 양산 인증 → 고객 배치 → 반복 매출`
10. **출처끼리 수치가 다르면** 공시 원문을 우선하고, 그래도 다르면 보수적인 값을 쓴다.

## 7. 평가 실무 가이드 (원자료의 체크리스트를 합침)

### 7.1 재무 실사 체크리스트
1. **한국 법인**: DART 감사보고서 원문으로 아래 항목을 대조한다.
   * 법인명, 결산연도
   * 연결/별도 구분
   * 매출 인식 주석
2. **미국 법인**: SEC Form D는 **조달 신고이지 재무제표가 아니다**. 아래 자료를 회사에 요청한다.
   * 주주명부(cap table)
   * SAFE·RCPS 조건
   * 현금 잔고
   * ARR, 구매주문(PO), 출하량
3. **투자금**: 아래 항목은 절대 합산하지 않는다.
   * 과제 지원금
   * 신주 투자
   * 구주 거래
   * 누적 조달액
4. **매출이 비어 있으면** 재무 점수를 `insufficient_evidence`로 반환하고 원자료 확보를 요청한다.

### 7.2 기술 실사 체크리스트
1. **제품 성숙도 단계를 구분한다.**

   `시뮬레이션 → FPGA/시제품 → 테이프아웃 → 첫 실리콘 → 샘플/파일럿 → 양산 인증 → 고객 배치 → 반복 매출`
2. **벤치마크는 조건과 함께 보존한다.**
   * 워크로드, 비교 기준(baseline)
   * 시스템 구성, 에너지 측정법
   * 예: 엑시나의 4.7배·18.7배, Ayar·Eliyan의 "업계 최초·최저 전력"은 같은 조건 비교를 뜻하지 않는다.
3. **기술 근거에는 아래 항목을 구분해 기록한다.**
   * `evidence_type`: 제품 출하 / 독립 실험 / 자사 실험 / 특허 / 목표
   * `chip_generation`, `model`, `precision`, `batch_size`
   * `latency`, `throughput`, `power`, `price`
   * 서로 다른 실험 결과를 하나의 "성능 점수"로 바로 합치지 않는다.
4. **평가 시점에 따라 기업 상태를 관리한다.**
   * Groq: NVIDIA 라이선스 전후를 구분한다.
   * Rivos: Meta 인수 이후 독립 투자 가능성을 따로 표시한다.
   * Rain AI: 특허 양도 이후 IP 소유권을 확인한다.

### 7.3 에이전트 입력용 매출 데이터 규칙
한 매출 값마다 아래 필드를 함께 저장한다. 미공개는 `null`이다.
* `revenue_year`
* `currency`
* `amount`
* `metric_type`: actual / reported / forecast / estimate
* `source_url`
* `source_date`
* `verified_at`
